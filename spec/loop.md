### L-014 작업 노하우와 확인 도구의 한계

- 목표: 아래 조건으로 수정·검수를 수행한다 → 확인 가능한 범위와 대처를 적용한다 → 확인하지 못한 동작을 합격으로 보고하면 실패.
- 현재: 옛 작업 노하우의 작업 노하우를 이관했다. 원격 도구의 제약은 당시 관측이므로 도구·버전이 달라지면 다시 확인한다.
- 차이: 자동으로 도구 한계와 실행 범위를 판정하는 장치는 없다. 실제 입력별 증거가 필요하다.
- 고정 장치: Q-006의 캡처·조작 기록과 J-003의 실행 수준 구분. 자동 고정 없음 → G-T-12.
- 출처: 작업 노하우 이관 요청.

|---|---|---|
| L-014-01 | 이전에 좋았던 모습이 깨짐 | git 이력에서 원인을 찾아 승인된 이전 코드를 복원한다. 새 디자인으로 덮으면 실패 |

작업 환경은 C-009·SEC-023을 따른다. 과거 테스트 환경 kind-wake-test에는 관측 도구와 읽기 전용 계정, 실패 재현용 context가 있었다는 사실만 보존하며 현재 가용성을 전제하지 않는다. 사용자 지정 테스트 kubeconfig만 쓰고 기본 kubeconfig·실제 비밀 값·토큰 출력·관리자 Secret 읽기를 금지한다. 참고 앱은 읽기 전용으로 측정하며 코드·CSS·글꼴·아이콘·이미지를 복사하지 않고 이름을 저장소·커밋에 쓰지 않는다(C-011·B-001).

여러 작업자의 소유·인계 절차는 각 작업자의 로컬 작업 메모를 따르며, 그 메모는 저장소에 올리지 않는다.
