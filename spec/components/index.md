# 부품 목표 명세

빈 Pod 목록도 열 머리와 빈 행을 유지하고, 같은 이름으로 재생성된 Pod는 이전 UID의 선택과 관측을 물려받지 않는다. 이런 기대 동작은 목표에, 현재 구현과 아직 남은 차이는 별도 필드에 둔다.

## 읽는 순서

1. [공통 표 계약](table-contract.md): 열 의미, 7상태, 대상 식별, 폭, 정렬, 값, 내보내기, 검수
2. [열 색인](column-inventory.md): 직접 169열·리소스 종류별 130열과 각 표 문서
3. [리소스 값](resource-values.md), [카드](cards.md), [차트](charts.md), [흐름 그래프](flow-graph.md), [출처 칩](source-chips.md)
4. [컨트롤](controls.md), [입력 정의](control-inventory.md), [코드·로그·근거](code-evidence.md), [인시던트 판단](incident-criteria.md)
5. [회귀 근거](regressions.md)

## 형식과 근거

- 목표는 검사할 동작이다. 정렬·임계값·폭은 decisions.md의 확정 결정과 기본값 채택을 따른다. 구현 완료는 별도로 검증한다.
- 현재는 코드 위치와 정적 사실 한 줄이다. 차이의 TASK-CMP ID는 남은 작업의 연결키다.
- 고정 장치는 실재하는 시험 파일과 시험 이름 또는 점검 도구 항목이다. 파일 존재는 시험 실행이나 native·실제 클러스터 검증 통과를 뜻하지 않는다. 해당 요구의 장치가 없으면 고정 없음과 TASK ID를 연결한다.
- 열·카드·입력 정의의 표 행은 상위 공통 계약의 현재·고정 장치·출처를 상속하며 대상별 식과 예외만 둔다. 공통 규칙을 각 열에 복사하지 않는다.
- 원장 질문·붙여넣은 보고·시연·운영 지시는 독립 승인과 구별한다. 후속 결정은 같은 대상과 범위에만 적용한다. 단일 정본 표도 실제로 독립된 하위 표가 있으면 정렬·대상·검색 정책을 각각 명시한다.

## 재검사

표의 직접 열과 종류별 열 299개의 기존 ID를 보존하고, 비용 7열 확장·공유 Event 3열·Restarts 및 skeleton 공장은 별도로 추적한다. 수집 이후 코드가 바뀌면 식과 행번호를 다시 대조한다.

문서 검사는 분량, 열 ID 보존, 내부 링크, 실제 코드·시험 경로를 대상으로 한다. 제품 시험·Electron 캡처·실제 클러스터 조회는 문서 변경의 검증 범위가 아니다.
