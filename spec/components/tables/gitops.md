# GitOps Application과 Helm 목록

[공통 표 계약](../table-contract.md)의 CMP-TABLE-01~08을 상속한다. 숫자 정렬과 기본 정렬은 D-USR-2026-11-16-1·2를 따른다. 그 밖의 검색·필터 추천안은 D-USR-2026-11-16-7의 기본값이다. 열의 값·정렬·톤·툴팁·폭은 아래 열 계약에 적는다. 공통 정렬·빈 값 처리는 CMP-TABLE-01~08을 참조한다.

## CMP-T-GITOPS-01

- 목표: gitops Application에 Degraded와 Healthy를 넣고 Helm 리소스 라벨만 있는 클러스터를 연다 → Degraded Application을 Healthy 앞에 두고 Helm 라벨의 release-name·namespace·chart만 표시한다. Application 동기화·건강은 해당 API에서 읽는다. Helm은 D-01에 따라 Secret 없이 확인한 릴리스 이름·namespace·chart·소속 리소스만 표시한다. 허용 출처는 meta.helm.sh/release-name·release-namespace, app.kubernetes.io/managed-by·instance 등의 리소스 주석/라벨, helm.sh/chart 및 Argo CD Application의 helm source다. 없는 라벨은 확인 불가이며 revision·status·이력은 “권한 범위 밖(Secret)”이다; [RULE-SORT](../../rules.md#RULE-SORT). 문제 우선: 상태 톤 위험·주의만 먼저 두며 읽기 실패·무계측을 정상으로 보지 않음. 행 이동: 같은 provider·cluster·namespace·이름의 GitOps 상세. 검색·거르기: name·namespace·source·revision 검색, provider·상태·기간; Helm status·revision을 Secret에서 읽거나 Degraded가 정상 행 뒤에 놓이면 실패.
- 현재: appRows가 appBad 내림 뒤 name.localeCompare로 정렬한다(`apps/wake/data/gitops.js:134–139`); 페이지는 이 결과를 slice한다(`apps/wake/pages/gitops.js:71`).
- 차이: appBad는 문제 유무만 나눠 danger/warn 단계와 namespace·UID 동점을 반영하지 않는다. name.localeCompare는 코드포인트 비교가 아니다. Helm 공급원은 Secret 기반이다.
- 고정 장치: 고정 없음 → TASK-CMP-T-GITOPS
- 출처: D00100 D-01 D00450; D-USR-2026-11-16-2; D00447; D01051. 그 밖의 검색·필터 기본값은 D-USR-2026-11-16-7.
